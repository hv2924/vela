01 — Getting Started

Introduction

Vela is a strongly typed programming language built around a simple idea: the more meaning the compiler understands, the more it can protect, validate, and optimize on the programmer's behalf.

Release · 0.0.1 First public iteration

§What is Vela?

Vela is a statically typed language that compiles Vela source through lexical analysis, parsing, semantic analysis, and code generation into JavaScript backed by a focused runtime. Its type system is designed around meaningful domain concepts as well as conventional programming types, allowing values such as money, secret, email, and uuid to carry semantics that the compiler can understand.

The language is designed to keep programs readable while making important mistakes difficult to express. Collections, entities, permissions, first-class functions, typed input, exact decimal arithmetic, and compiler-directed weave() pipelines all build on that same principle.

§Design Principles

Vela's design is guided by a small set of principles: make intent visible in the program, give the compiler enough information to enforce meaningful guarantees, and keep high-level code readable even when the generated execution is highly optimized.

01

Readable by design

Vela favors explicit, compact syntax that keeps the programmer's intent visible without requiring unnecessary ceremony.

02

Meaningful type safety

Important concepts such as money, secrets, collections, entities, and permissions are understood by the compiler instead of being reduced to generic values.

03

Optimization through meaning

Because Vela understands higher-level operations, the compiler can fuse compatible collection stages and eliminate unnecessary intermediate work.

04

Explicit over implicit

Vela prefers important decisions to be visible in source code, from currency conversion to sensitive input and collection transformations.

0.0.1 Vela 0.0.1 is the first public iteration of the language. Start with the installation guide, run the first example, then explore the type system and compiler-driven features.
02 — Getting Started

Installation

Vela 0.0.1 is distributed as an open-source compiler project. The current implementation runs on Node.js and compiles Vela source into JavaScript, making the first release straightforward to build and experiment with from source.

§Prerequisites

The current 0.0.1 compiler requires Node.js, npm, and the project's TypeScript/JavaScript toolchain.

  • Node.js
  • npm
  • Git for building from the source repository

npm run typecheck

Vela's current compiler is developed in TypeScript and executed with Node.js. Install the project dependencies, verify the compiler, and compile a Vela source file with the commands below.

node dist/hello.js

03 — Getting Started

Hello World

Start with a tiny Vela program, compile it to JavaScript, and run the generated program with Node.js. This example introduces Vela's function syntax, typed values, and basic output.

A Vela program can begin with a simple function and a call to print. The example below keeps everything visible: the function declaration, its return type, the input value, and the final output.

hello.vela 
fn greet(name: text) -> text {
    return "Hello, " + name
}

let name: text = "World"
print(greet(name))

The greet function accepts a text value and returns another text value. The type annotation makes that contract explicit to the compiler. The print built-in then writes the returned value to standard output.

Vela's current 0.0.1 workflow compiles the source file into JavaScript rather than executing the .vela file directly. The generated JavaScript can then be run with Node.js.

terminal 
npm run vela -- examples/hello.vela
node dist/hello.js

# Hello, World!

04 — Language

Data Types

Vela is a statically typed language with explicit type annotations, type-aware expressions, and domain-specific types built directly into the language and compiler.

§Primitive Types

Vela's primitive types cover common values as well as concepts that benefit from stronger semantics. Types are checked by the compiler rather than being treated as interchangeable runtime values.

Text [text]
Text values represented as strings in generated JavaScript.
let name: text = "Vela"
Integer [int]
Whole-number values used throughout the language and collection APIs.
let count: int = 42
Boolean [bool]
Boolean values used for conditions, predicates, permissions, and logical expressions.
let active: bool = true
Decimal [decimal]
Exact decimal values intended for calculations where ordinary binary floating-point behavior is undesirable.
let rate: decimal = 1.25
Email [email]
A domain-aware email value with compiler-visible type information.
let address: email = "user@example.com"
UUID [uuid]
A dedicated UUID type for identifiers that should remain distinct from ordinary text.
let id: uuid = ...
Secret [secret]
A sensitive value intended to be handled differently from ordinary text, including secure input.
let password: secret = ...
Secret Hash [secret_hash]
A hashed secret value produced by the language runtime's password-hashing facilities.
let hash: secret_hash = ...
Money [money]
Currency-aware monetary values with exact minor-unit storage and currency-aware arithmetic.
let price: money = ...

§Entities

Entities are named domain types defined directly in Vela. Their fields have explicit types, allowing the compiler to reason about relationships between values and domain objects.

entities.vela 
entity User {
    id: int
}

§Collection Types

Vela provides typed collections whose element, key, and value types are part of the type system. Collections can also be nested, allowing structures such as list[list[int]].

List list[T]
An ordered collection of values sharing a single element type.
let values: list[int] = list(1, 2, 3)
Set set[T]
A collection of unique values with hash-based membership checks.
let values: set[int] = set(1, 2, 2, 3)
Map map[K,V]
A key-value collection with explicit key and value types.
let users: map[text,int] = map("alice", 10)
Function (T...) -> R
A first-class function value with typed parameters and a typed return value.
let op: (int) -> int = double

§Type Inference

Type annotations can be written explicitly where they make intent clear, while expressions can also provide enough information for the compiler to determine their type. Generic collection types remain explicit about the types of the values they contain.

inference.vela 
let count = 42
let message: text = "hello"
let values: list[int] = list(1, 2, 3)
05 — Language

Variables & Scope

Vela bindings are introduced with let. Types may be written explicitly when needed, while the initializer can provide the information required for type analysis.

§Declaration

A variable declaration uses let, followed by a name and, when desired, an explicit type annotation. The initializer determines the value assigned to the binding.

variables.vela 
let count = 10
let name: text = "Vela"

let numbers: list[int] = list(1, 2, 3)
let operation: (int) -> int = double

§Typed Bindings

Explicit annotations are particularly useful for domain types, generic collections, and first-class functions. They communicate the intended type directly to both the reader and the compiler.

typed-bindings.vela 
let email: email = ...
let scores: list[int] = list(10, 20, 30)
let lookup: map[text,int] = map("alice", 10)

§Collections Are Values

Collection values can be passed to functions and transformed by the collection APIs. Operations such as append and mapSet operate on the collection value itself, while the compiler continues to track its declared type.

collections.vela 
let numbers: list[int] = list(1, 2)

append(numbers, 3)

let users: map[text,int] = map("alice", 1)
mapSet(users, "bob", 2)
06 — Language

Functions

Functions are the primary unit of executable behavior in Vela. They have explicitly typed parameters and return types, and function values can be stored, passed to other functions, and called dynamically.

§Declaration

A function is declared with fn, followed by its name, typed parameters, and a return type. The function body contains the expressions that implement its behavior.

functions.vela 
fn add(a: int, b: int) -> int {
    return a + b
}

let result = add(3, 4)

print(result)

§Parameters & Return Types

Parameter types and return types are part of a function's signature. The compiler checks calls against that signature, including the number and types of supplied arguments.

typed-functions.vela 
fn isLongerThan(value: text, limit: int) -> bool {
    return length(value) > limit
}

§First-Class Functions

Functions can be used as values. Vela represents a function value with a function type describing its parameter types and return type.

function-values.vela 
fn double(value: int) -> int {
    return value * 2
}

let operation: (int) -> int = double

print(operation(5))

§Higher-Order Functions

Because functions are values, they can be passed to other functions. This is the foundation for Vela's typed collection algorithms such as filter, map, and reduce.

higher-order.vela 
fn isEven(value: int) -> bool {
    return value % 2 == 0
}

let numbers: list[int] = list(1, 2, 3, 4)

let evens = filter(numbers, isEven)

print(length(evens))
07 — Language

Control Flow

Vela keeps control flow deliberately small in its first public iteration, with conditional execution providing the foundation for branching behavior.

§Conditionals

Conditional branches use if, with optional else if and else branches. Conditions are boolean expressions, so the compiler can check that a branch receives the appropriate value.

conditionals.vela 
let value: int = 10

if value > 0 {
    print("positive")
} else if value < 0 {
    print("negative")
} else {
    print("zero")
}

§Boolean Expressions

Comparisons and logical expressions produce bool values and can be used directly as conditions. This keeps branching explicit while allowing conditions to be composed from ordinary expressions.

conditions.vela 
let age: int = 21
let verified: bool = true

if age >= 18 && verified {
    print("access granted")
}
0.0.1 Control-flow features will continue to grow with the language. This release keeps the documented surface focused on the constructs currently established in the compiler.
08 — Libraries

Data Algorithms

Vela's collection algorithms combine strong typing with first-class functions, giving common transformations a compact syntax while leaving their input and output types visible to the compiler.

§Map

map transforms every element of a list with a typed function. The output list may have a different element type from the input.

map.vela 
fn double(value: int) -> int {
    return value * 2
}

let numbers: list[int] = list(1, 2, 3)
let doubled = map(numbers, double)

print(get(doubled, 1))

§Filter

filter keeps the elements for which a typed predicate returns true. The element type of the resulting list remains the same as the input.

filter.vela 
fn isEven(value: int) -> bool {
    return value % 2 == 0
}

let numbers: list[int] = list(1, 2, 3, 4)

let evens = filter(numbers, isEven)

print(length(evens))

§Reduce

reduce folds a list into a single accumulator value. Its reducer receives the current accumulator and the current element and returns the next accumulator.

reduce.vela 
fn add(total: int, value: int) -> int {
    return total + value
}

let numbers: list[int] = list(1, 2, 3, 4)

let total = reduce(numbers, 0, add)

print(total)

§Weave

weave is Vela's compiler-aware collection pipeline primitive. It expresses a sequence of collection stages as one operation, allowing the compiler and runtime to execute compatible stages together instead of requiring every intermediate collection to be materialized.

weave.vela 
fn isEven(value: int) -> bool {
    return value % 2 == 0
}

fn double(value: int) -> int {
    return value * 2
}

fn greaterThanFive(value: int) -> bool {
    return value > 5
}

let numbers: list[int] = list(1, 2, 3, 4, 5, 6)

let result = weave(
    numbers,
    filter(isEven),
    map(double),
    filter(greaterThanFive)
)

§Early Termination

A final find stage can terminate a weave pipeline as soon as a matching value is produced. This makes searches expressible without requiring a separate full traversal after the preceding stages.

weave-find.vela 
fn isEven(value: int) -> bool {
    return value % 2 == 0
}

let numbers: list[int] = list(1, 2, 3, 4, 5, 6)

let result = weave(
    numbers,
    filter(isEven),
    find(greaterThanFive)
)
Vela Collection pipelines are not merely a convenience API. weave() gives the compiler a structured representation of the programmer's intent, creating room for execution strategies that ordinary chained collection calls cannot express as directly.
09 — Libraries

Standard Library

Vela 0.0.1 keeps its standard runtime deliberately focused. Core operations are exposed directly through typed built-ins, with the compiler providing semantic checks before execution.

§Input & Output

print writes a value to standard output. input reads user input and can also be parameterized with a Vela type to request structured typed values.

input.vela 
let name: text = input()

print(name)

§Secrets & Passwords

Sensitive values have dedicated types and runtime operations rather than being treated as ordinary text. Vela provides secure secret input together with password hashing and verification.

secrets.vela 
let password: secret = input[secret]()
let hash: secret_hash = velaHash(password)

let valid = velaVerify(password, hash)

§Collections

Collection construction and manipulation are available directly through typed built-ins. The compiler checks the relationships between collection types and their arguments.

Lists
Ordered collections with length, indexed access, append, membership, and higher-order algorithms.
list(1, 2, 3)
Sets
Unique-value collections with hash-based membership checking.
set(1, 2, 2, 3)
Maps
Typed key-value collections with lookup, mutation, and membership operations.
map("alice", 10)
Pipelines
Compiler-aware collection execution through weave and early-terminating find.
weave(...)

§Money

The money runtime provides currency-aware monetary values, exact minor-unit storage, arithmetic, and rounding behavior. Monetary operations preserve the currency relationship enforced by the compiler and runtime.

money.vela 
let price = money(19.99, "EUR")

§Permissions

Entity permissions are represented as part of Vela's domain model. A permission expression can be evaluated with can, allowing authorization logic to remain connected to the entity definition.

permissions.vela 
entity Task {
    id: int
    owner: User

    permission edit = owner
}

let allowed = can(user, "edit", task)
0.0.1 The runtime is intentionally compact in the first release. Additional libraries and integrations can grow around the core language without forcing the initial standard library to become a large surface area.
10 — Resources

Examples

These examples demonstrate the ideas that make Vela distinct: explicit types, domain-aware entities, typed input, and compiler-aware collection processing.

§Collection Pipeline

Vela's collection operations can be combined into a weave pipeline. The pipeline describes the intended stages directly, allowing the compiler and runtime to execute compatible operations together instead of materializing every intermediate collection.

collection_pipeline.vela 
fn isEven(value: int) -> bool {
    return value % 2 == 0
}

fn double(value: int) -> int {
    return value * 2
}

let numbers: list[int] = list(1, 2, 3, 4, 5, 6)

let result = weave(
    numbers,
    filter(isEven),
    map(double)
)

print(result)

§Entities & Permissions

Entities allow application concepts to be represented directly in the language. Permissions can be declared alongside the entity and evaluated with can, keeping authorization rules close to the data they govern.

permissions.vela 
entity User {
    id: int
}

entity Task {
    id: int
    owner: User

    permission edit = owner
}

let allowed = can(alice, "edit", task)

print(allowed)

§Typed Input

Input is not limited to raw text. Vela can request values using a type expression, allowing the runtime to validate and construct structured values according to the requested type.

typed_input.vela 
let age: int = input[int]()
let tags: list[text] = input[list[text]]()
let choices: set[int] = input[set[int]]()

print(age)
print(tags)
print(choices)

§Secure Secret Input

Sensitive values have their own type. Requesting secret input uses the secure input path rather than treating a password as ordinary text.

secret_input.vela 
let password: secret = input[secret]()

print("Secret received.")

§Exact Money

Money is represented as a domain-specific value rather than an unstructured number. Currency is part of the value, and monetary arithmetic is performed with exact decimal semantics.

money.vela 
let price = money(19.99, "EUR")
let quantity: int = 3

let total = price * quantity

print(total)

§Release Notes

Vela v0.0.1 is the first public iteration of the language and establishes the foundation for future releases. The release brings together the compiler, semantic type system, domain-aware values, collections, entities, permissions, typed input, and compiler-aware collection pipelines.

The release includes exact decimal and money handling, secure secret input, password hashing and verification, typed lists, sets and maps, first-class functions, and the weave collection execution model. Collection pipelines can express filtering, mapping, and finding in a form the compiler can analyze and optimize.

Vela is intentionally evolving. APIs, syntax, compiler behavior, and runtime capabilities may change as the language moves beyond the 0.0.1 foundation.

0.0.1 This is an early public release. Expect the language to evolve rapidly as new iterations build on the foundations established here. Report bugs, unexpected compiler behavior, and documentation issues through the project's GitHub repository.

Contributing

Vela is an evolving language and compiler project, and contributions are welcome. Bug reports, language experiments, compiler improvements, documentation updates, and new examples all help shape future iterations.

§Getting the Source

Vela is developed as a TypeScript compiler project. Start by cloning the repository, installing its dependencies, and checking that the compiler project passes its type check.

terminal 
git clone <repository-url>
cd vela
npm install
npm run typecheck

§Development Workflow

Contributions should follow the existing project structure and preserve the compiler's semantic guarantees. When changing language behavior, update the relevant compiler logic and add or adjust tests so the new behavior can be verified before it becomes part of a release.

  1. Fork or clone the repository and create a branch for your change.
  2. Make the smallest focused change that solves the problem or adds the intended feature.
  3. Add or update tests for compiler, semantic, runtime, or language behavior affected by the change.
  4. Run the project's type check and relevant tests before submitting the change.
  5. Open a pull request describing what changed, why it changed, and any language or compiler behavior affected.

§Reporting Issues

When reporting a bug, include the smallest Vela source example that reproduces the problem, the compiler output or runtime error, and the behavior you expected. For compiler issues, also include the relevant command used to reproduce the problem.

§Language Changes

Changes to Vela's syntax, type system, runtime behavior, or compiler semantics should be considered carefully because the language is intentionally evolving between iterations. Explain the intended behavior clearly and keep the implementation, tests, and documentation aligned.

§Code of Conduct

Contributions should be respectful, constructive, and focused on improving Vela. A formal Code of Conduct can be added to the repository as the project's community guidelines develop.

Vela Vela is being built iteratively. A good contribution does not have to be large — a clearer diagnostic, a better test, a documentation fix, or a small compiler improvement can make the next iteration stronger.
